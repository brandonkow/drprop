# Dr Prop app preview

The Expo SDK 57 / React Native / Expo Router application is under `app/`, isolated from the vanilla Vite website. It uses the shared `brand/tokens.ts`, self-hosted Instrument Serif/Geist/Geist Mono, exactly three text tabs and no default UI theme. Everything is English.

```sh
npm --prefix app ci
npm --prefix app start
npm --prefix app run web
npm --prefix app run typecheck
npm --prefix app test
npm --prefix app run export:web
npm --prefix app run export:native
npx playwright test --config playwright.app.config.ts
```

`export:web` writes `app/dist`; `export:native` writes `app/dist-native`. Native export is a JavaScript/assets bundling check, not a signed APK/IPA, device test or store release. Use Expo Go compatible with SDK 57 or a development build for device verification. Windows cannot locally compile iOS. No EAS project/account or paid build job is configured.

## Preview journey

- S0: 800ms line draw/roof transition and wordmark fade, bypassed for reduced motion.
- S1: phone, preview OTP `246810`, preferred name. Try `+60 12 345 6789`. No SMS is sent and no phone ownership is verified.
- S2: personal greeting, one primary booking button, sample lounge availability/coffee and membership link.
- S3: four booking screens: type; price band/documents; appointment/callback; fee/payment confirmation. The success state replaces the fourth screen. All payments are explicitly simulated. Urgent fees use 1.5 times the proposed standard fee; final checks use half price and must reference a completed case at the same price band.
- S4: chronological local records, sample PDF/adviser questions, final-check booking and cancellation. Use “Load fictional sample record” to explore a completed case; real bookings do not turn into fabricated diagnoses.
- S5: portrait night-metal card, native Skia shader, optional gyroscope, actual QR encoding a deliberately invalid demo token. Reduced motion, denied permission, missing sensors and backgrounding preserve the usable card. Web uses an SVG metal surface; native Skia needs device verification.
- S6: name/drink, simulated renewal, paper/night/system appearance, fixed English and sign out.

Native pulse rendering uses Skia and Reanimated. The web pulse uses SVG and Reanimated. A success haptic is requested after booking and gracefully ignored when unsupported.

## Data boundaries

The `DemoProvider` stores a versioned local preview under `drprop.preview.v1` using AsyncStorage. This is not an authentication or sensitive-data storage system. UI copy requests sample details only. Sign out clears demo records/preferences; there is no backend, telemetry or file upload. Picked documents retain only name/type/size, never contents or access URLs. Maximum three PDF/JPG/PNG/WebP files, 10 MB each.

Store seat counts, membership state, coffee and dates are explicitly demo data. Membership price, commercial terms and real availability remain unconfirmed. The QR is not an access credential. Reception cannot see local preferences until a later authenticated staff/backend integration is built.

## Phase-two integration points

Replace the demo repository with an authenticated service for OTP, per-user consultation/attachment access, staff preferences, schedules, expiring check-in tokens, server-calculated fees, signed PDF URLs and idempotent payment webhooks. Payment success must be verified server-side. The current simulated payment is never a production gateway fallback. Choose and configure the actual provider separately.

The bundled sample diagnosis is generated by `scripts/create-sample-report.py` using ReportLab and the app's font dependencies. It is fictional and contains no assessed property facts.

To reproduce the PDF after installing app dependencies (validated with Python 3.12):

```sh
python -m pip install -r scripts/requirements-report.txt
python scripts/create-sample-report.py
```

Render and visually inspect a changed report before exporting the app again. The shipped PDF is already included, so Python is not required to run the preview.

## Dependency compatibility and verification

Expo Router's query-string dependency uses an older decoder. The lockfile overrides it with decode-uri-component 0.5.0; the idempotent `postinstall` adapter handles its ESM default export while retaining query-string 7.1.3's API. It stops on an unexpected version instead of silently patching incompatible code. Xcode's UUID dependency is pinned to compatible 11.1.1. Tests exercise Unicode/malformed route decoding and valid Xcode identifiers. Reassess these overrides when upgrading Expo.

On 2026-09-29, all nine unit tests, TypeScript, web export, Android/iOS JavaScript exports and three browser journeys passed. The production dependency audit reports zero known vulnerabilities at that date. Browser coverage includes four-screen booking, attachments, reload/cancellation, report viewing, linked follow-up, membership, theme/profile persistence, renewal simulation, invalid login, accessibility, 320px layout and clearing local state.

Native sensors, Skia output, haptics and platform file sharing still require physical-device testing. Export success is not a native runtime or store-submission certification.
